# SockDock for Slack — 情報設計

画面に何を載せるかを決める文書です。UI を変えるときは、先にこの文書を直します。
モック: [`docs/mock/index.html`](mock/index.html)

## 1. 拠りどころにする一般論

| 一般論 | 要点 | この設計での使い方 |
|---|---|---|
| 段階的開示（NN/g） | よく使うものだけを最初に出し、まれなものは 2 段目へ。3 段以上にしない。2 段目への入口は、何があるかがわかる名前にする | 最初の画面は「ルールの一覧」だけ。まれな操作は 2 段目までに収める |
| 段階的な手順（NN/g） | 互いに独立した少数の手順なら、順に見せる。手順が多すぎると移動が増える | セットアップは 2 手順だけ |
| Disclosure（Dan Brown） | その先に何があるかがわかる分だけを見せる | 説明は 1 文まで。手順は、やることの名前だけを示す |
| Choices（Dan Brown） | 画面ごとの選択肢を、その作業に絞る | 1 画面 1 作業。作業に関係のない状態や説明を載せない |
| Front doors（Dan Brown） | 利用者の多くは、ホーム以外の入口から来る | 入口は通知とメニューバー。そこから目的の画面へ直接開く |
| オンボーディング（Apple HIG） | 使ってみればわかるのが理想。必要なら短く、覚えることを求めない。説明は一連の流れより、その場所の近くに置く。必須でない設定は後回しにして、妥当な既定値で始める | セットアップは接続だけ。ルールの説明は、ルールを作る画面に置く。ログイン時の起動などは設定へ |
| メニューバー（Apple HIG） | アイコンを押したらメニューを出す（ポップオーバーではなく）。メニューバーにあることを当てにしない | メニューバーは状態と入口だけのメニュー。同じことはウィンドウでもできる |
| メンタルモデル | 作る側の仕組みではなく、利用者の頭の中の分け方に合わせる | 利用者の頭の中にあるのは「Slack」と「ルール」だけ。ゲートウェイや Socket Mode は出さない |

出典: [Dan Brown, Eight Principles of Information Architecture](https://principles.design/examples/eight-principles-of-information-architecture) / [NN/g, Progressive Disclosure](https://www.nngroup.com/articles/progressive-disclosure/) / [NN/g, IA vs. Navigation](https://www.nngroup.com/articles/ia-vs-navigation/) / [Apple HIG, Onboarding](https://developer.apple.com/design/human-interface-guidelines/onboarding) / [Apple HIG, The menu bar](https://developer.apple.com/design/human-interface-guidelines/the-menu-bar)

**方針: わからなさを、説明を足して解かない。** 画面の数・言葉の数・選択肢の数を減らして解く。説明が要るのは、その場で判断が要るとき（例: 誰でも動かせるチャンネルを選ぶとき）だけ。

## 2. 利用者の文脈

利用者は、Claude Code などの AI エージェントやスクリプトを日常的に使う開発者です。Homebrew で SockDock を入れました。Slack は毎日開いています。

| 場面 | 頻度 | いる場所 | したいこと |
|---|---|---|---|
| つなぐ | 1 回 | SockDock のウィンドウと、ブラウザの api.slack.com | 早く終わらせたい |
| ルールを作る・変える | ときどき | SockDock のウィンドウ | チャンネルと、反応する投稿と、動かすものを決める |
| 使う | 毎日 | **Slack**（SockDock は見ない） | 投稿して、返信を受け取る |
| おかしいと気づく | まれ | Slack、通知、メニューバー | 何が起きたかを見て、直す |

いちばん多い「使う」場面では、SockDock の画面を見ません。だから日常の画面は要りません。SockDock の画面は「つなぐ」「ルールを作る」「おかしいときに見る」ためのものです。

## 3. Slack 上での動き

「使う」場面の画面は Slack です。SockDock が Slack に出すのは、投稿への 👀 と、スレッドへの返信だけです。

| 起きたこと | Slack で見えること | 伝えたいこと |
|---|---|---|
| 投稿がルールに合った | 投稿に 👀 が付く | 受け取って、処理している |
| 処理が終わった | 👀 が外れ、スレッドに返信が付く | 結果はこのスレッドにある |
| そのスレッドに返信した | 同じルールで続きを処理する。AI エージェントは前のやりとりを覚えている | 続きはスレッドで話せばよい |
| ルールに合わない投稿 | 何も起きない | 関係のない投稿には反応しない |
| 投稿を編集した | 何も起きない | 動かしたいときは、投稿し直す |
| 実行できる人を選んだルールに、選ばれていない人が投稿した | 何も起きない | ルールに合わない投稿と同じ。ルールがあることも見せない |
| そのスレッドに、選ばれていない人が返信した | 何も起きない。AI エージェントにもプログラムにも渡さない | 会話を続けられるのは、選ばれた人だけ |
| Slack アプリに DM した | チャンネルへの投稿と同じ。DM のメッセージに 👀 が付き、そのスレッドに返信が付く | DM もチャンネルと同じように使える |
| 「メンションされたときだけ」のルールに、メンションのない投稿をした | 何も起きない | 動かしたいときは、Slack アプリをメンションする |
| スレッドの途中で Slack アプリをメンションした | 今までと同じ。ルールで始まったスレッドでなければ、何も起きない | ルールを始められるのは、トップレベルの投稿だけ |
| ファイルを付けて投稿・返信した | 本文と一緒に、ファイルも AI エージェントやプログラムに渡る（§8「添付ファイル」） | 「このスクショを見て」と頼めばよい |
| 渡せないファイルを付けた（大きすぎる、Slack の外のファイルなど） | 本文とほかのファイルで、いつもどおり動く。見ていないことは、AI エージェントが返信の中で伝える | そのファイルは見ていない |
| うまくいかなかった | スレッドに定型文が付く（下の表） | 何が起きたか。次にどうすればよいか |

プログラムの標準出力が空なら、返信しません（👀 が外れるだけ）。

### 定型文

定型文を読むのは投稿した人です。Mac の画面は見ていないかもしれません。スレッドの中なので、どのルールかは書きません。

| いつ | 文言 | 伝えたいこと |
|---|---|---|
| 失敗した | ⚠️ 処理に失敗しました。理由は Mac の SockDock で確認できます。 | 自分の投稿のせいとは限らない。理由はあとで見られる |
| 上限時間を超えた | ⏱ 上限時間（600 秒）を超えたため停止しました。内容を分けて送ってください。 | 分ければ終わるかもしれない |
| Mac の画面で停止した | ⏹ 処理を停止しました。 | 止めたのは人で、故障ではない |
| 処理中に SockDock が終了した | ⚠️ 処理の途中で SockDock が終了したため、停止しました。もう一度送ってください。 | 送り直せば動く |
| オフのルールのスレッドに返信した | ⏸ このスレッドのルールはオフになっています。 | 今は動かない |
| 削除したルールのスレッドに返信した | ⚠️ このスレッドのルールは削除されています。 | もう動かない |
| AI エージェントの前の会話を引き継げなかった | ℹ️ 前の会話を引き継げなかったため、新しい会話として始めました。 | 前のやりとりを前提にしないでほしい |

### 本人への DM（2026-11-14、承認済み）

読むのは本人（§9）です。Mac の前にいないかもしれません。本人との DM のトップレベルに送ります。通知（下の表の 3 行目から）を送るのは、設定の「通知」で「Slack の DM」がオンのときだけです（§8「通知」）。登録の 2 つは、登録の操作への返事なので、いつも返します。

| いつ | 文言 | 伝えたいこと |
|---|---|---|
| 本人の登録で、違うコードが届いた | ⚠️ コードが違います。 | Mac に出ているコードを送り直せばよい。通知のスイッチに関係なく返す |
| 本人として登録した | ✅ 登録しました。SockDock からのお知らせは、この DM に届きます。 | 登録できた。この DM が何に使われるか。通知のスイッチに関係なく返す |
| Claude Code にサインインしていないと分かった | ⚠️ Claude Code にサインインしていないため、AI エージェントのルールが動きません。Mac の SockDock でサインインしてください。 | 何が動かないか。直すのは Mac（ルールの一覧の［ターミナルでサインイン］）。サインインし直すまで、もう送らない。（Codex を足したら）ほかのエージェントでも同じ形で、エージェントごとに 1 回（「Codex にサインインしていないため、Codex のルールが動きません。」）。Claude Code だけを使っているあいだは今の文のまま |
| MCP からルールを変えた | MCP から `#dev-help「review」` を変更しました（追加・削除・並べ替え・オン/オフも同じ形） | Mac の前にいなくても、知らない変更に気づける |
| 処理が失敗した（設定の「通知」で「処理の失敗も送る」をオンにしたときだけ） | ⚠️ `#dev-help「review」` の処理が失敗しました。上限時間（600 秒）を超えたため停止しました。 スレッド ↗ | どのルールが、なぜ失敗したか。スレッドを開けば投稿が分かる |
| 新しい版が出た | 🆕 SockDock 0.2.0 が出ました。 リリースノート ↗ | 何が変わったかはリンク先で見られる。更新は Mac のメニューバーからできる（§8「新しい版」） |

### 使うスコープ・使わないスコープ

| すること | スコープ |
|---|---|
| 投稿とスレッドの返信を受け取る | `channels:history` `groups:history` |
| 👀 を付け外しする | `reactions:write` |
| スレッドに返信する | `chat:write`（参加しているチャンネルだけ） |
| チャンネルの一覧を取る | `channels:read` `groups:read` |
| 実行できる人を名前で選ぶ | `users:read` |
| DM を受け取る | `im:history`。ほかに、イベント `message.im` と、App Home の Messages タブ（メッセージを送れるようにする）が要る |
| メンションを見分ける | 増やさない。メンションを含む投稿も、`message.channels` `message.groups` で届いている |
| 本人に DM を送る | `chat:write`。本人が登録のときに送ってきた DM に送る |
| 投稿に付いたファイルを渡す | `files:read`（任意）。読むのは、ルールが動いた投稿のファイルだけ |

次のスコープは使いません。必要な機能を持たないためです。

- `reactions:read` / `emoji:read`: 人が付けたリアクションやカスタム絵文字は読まない。投稿の本文の絵文字は `:smile:` のような文字で届く
- `usergroups:read`: 実行できる人はユーザーグループでは選ばない（人だけ）
- `chat:write.public`: 参加していないチャンネルには投稿しない
- `app_mentions:read`（イベント `app_mention`）: 同じ投稿が `message.channels` でも届くので、要らない
- `im:write`: 本人との DM は本人から始まるので、SockDock から DM を開かない（設定ファイルに手で本人を書いた場合に届くかを、実装のときに確かめ、要るかを決める。ユーザー確認済み。design.md §3.5）
- `im:read`: DM の一覧は要らない

## 4. 構成

```
セットアップ（1 回だけ）            SockDock のウィンドウ（1 つだけ）
  1 Slack アプリを作成               ［ルール｜設定］
  2 Slack に接続                     ルール: 一覧 └ ルール（フォームと、最近の処理）
                                     設定:   Slack（接続・本人）/ 一般 / 通知 / MCP / 初期状態に戻す

メニューバーのメニュー: 状態 · 処理中 · 最近の処理 · SockDock を開く · 設定… · 終了
```

- ウィンドウは 1 つ。上の［ルール｜設定］で切り替える。サイドバーはない。
- 階層は 2 段まで（一覧 → ルール）。ルールの画面でも［ルール｜設定］は出したまま。
- 一覧はチャンネルごとにまとめ、その中は上から順に照合する順番で並べる。
- ⌘, とメニューの「設定…」は、このウィンドウを「設定」の表示で開く。
- 設定を別のウィンドウにしない理由: 別ウィンドウは、アプリのメニュー（SockDock → 設定…）があるアプリの慣習。メニューバーのアプリにはアプリのメニューがなく、別ウィンドウにすると、探す場所も閉じる場所も 2 つになる。
- 処理の結果は、そのルールのページに置く。全体の履歴の画面は作らない（全体はメニューバーの「最近の処理」で足りる）。
- 設定ファイルは画面で編集しない。一覧の下の「設定ファイルを開く」で、いつものエディタで開く。

## 5. Slack から分かること・分からないこと

画面の言葉は、SockDock が実際に知っていることだけで作ります。

| 知りたいこと | 分かるか | 取り方 |
|---|---|---|
| つながったワークスペース | 分かる | Bot Token の `auth.test` |
| Slack アプリが参加しているチャンネルの名前と ID | 分かる | `users.conversations`（スコープ `channels:read` / `groups:read`）。一覧には名前を出し、保存するのは ID |
| 参加していないチャンネル | 出さない | 参加していないチャンネルの投稿は届かないので、選べても動かない |
| 貼られたチャンネル ID・リンクの名前 | スコープがあれば分かる | `conversations.info`。スコープがないときは ID のまま表示する |
| Slack アプリの表示名（`@` の後ろの名前） | **分からない**（古いアプリ）／使わない | `users:read` があれば取れるが、画面には出さない。`users:read` のない古いアプリでは取れない |
| ワークスペースのメンバーの名前と ID | `users:read` があれば分かる | `users.list`。実行できる人を選ぶ欄だけで使う。保存するのはメンバー ID |
| 投稿者の名前 | 出さない | `users:read` で取れるが、最近の処理には出さない。スレッドへのリンクから Slack で見てもらう |
| 本人（SockDock を使っている人）が誰か | **登録すれば分かる** | どちらのトークンからも分からない。Mac で登録を始め、そこに出るコードを本人が Slack アプリに DM で送る（§8「本人」）。登録しても、チャンネルのルールの既定は「全員」のまま（ユーザー確認済み。§8「実行できる人」） |
| 投稿に付いたファイルの中身 | `files:read` があれば分かる | イベントの `files[]` の URL から取る。Slack の外のファイル（Google ドライブなど）は取れない |
| 届いたメッセージが DM か | 分かる | イベントの `channel_type` が `im` |
| メッセージが Slack アプリをメンションしているか | 分かる | 本文の `<@Slack アプリのユーザー ID>`。ユーザー ID は `auth.test` で分かる |
| Messages タブで、メッセージを送れるようになっているか | **分からない** | どちらのトークンでも読めない。DM が 1 件でも届いたかで、代わりに伝える |
| Bot Token に付いているスコープ | 分かる | `auth.test` の応答ヘッダー `x-oauth-scopes`。接続のときに、必須のスコープが足りるか確かめる |
| 2 つのトークンが同じアプリのものか | **分からない** | App-Level Token のアプリ ID は、つないだときの最初のメッセージで分かる。Bot Token のアプリ ID は `users:read` がないと取れない |
| Slack アプリがイベントを受け取る設定か | **分からない** | どちらのトークンでも読めない |
| そのチャンネルの投稿が、つないでから 1 件でも届いたか | 分かる | 届いたメッセージのチャンネルを覚えておく。上の 2 つが分からない代わりに、ルールの画面で「まだ届いていない」を伝える |

表示名は古いアプリでは分からず、利用者がいつでも変えられるので、画面に `@SockDock` のような固定の名前は書きません。「Slack アプリ」と呼びます。利用者は自分で作ったアプリの名前を知っています。

## 6. スコープをどこで伝えるか

| スコープ | 誰が決めるか | 伝える場所 |
|---|---|---|
| Bot Token のスコープ、イベントの購読、Socket Mode | 新しく作るなら、マニフェストに入っている（利用者は選ばない）。すでにあるアプリを使うなら、利用者がそろえる | 新しく作る人には出さない。セットアップ 1 の畳んだ入口「すでにある Slack アプリを使う」の中に、名前と、マニフェストの該当部分のコピーを出す。必須のスコープが足りなければ、セットアップ 2 で足りないものの名前を出して止める。イベントは確かめられないので、届かないときにルールの画面で出す（検討: [`docs/research/2026-11-13-setup-existing-app.md`](research/2026-11-13-setup-existing-app.md)） |
| App-Level Token の `connections:write` | 利用者がトークンの発行時に選ぶ | セットアップ 1 の「App-Level Token を発行」の行。選び忘れたときは、セットアップ 2 のエラーで伝える |
| 足りないスコープ（古いマニフェストで作ったアプリ） | — | 困った場所で伝える。チャンネル一覧が取れないとき、その欄に足りないスコープの名前を出す。`users:read` がないときは、実行できる人の欄に出す（セットアップでは止めない。実行できる人を選ばない人には要らないため） |
| `files:read`（古いマニフェストで作ったアプリ） | — | 困った場所で伝える。ファイルを付けたのに渡らなかった処理の行（ルールの画面の「最近の処理」）で、`files:read` のスコープがないことだけを伝える。足し方は案内しない（DM と同じ）。セットアップでは止めない（ファイルを渡さなくてもルールは動くため） |
| DM に要る設定（`im:history`、イベント `message.im`、Messages タブ。古いマニフェストで作ったアプリ） | — | 困った場所で伝える。ルールのチャンネルで DM を選んだときと、設定の「本人」で、`im:history` のスコープがないことだけを伝える。足し方は案内しない（いまは古いマニフェストで作ったアプリを考えなくてよいため。2026-11-14、ユーザー確認済み）。イベントと Messages タブは確かめられないので、DM が届かないときの手がかりに出す。セットアップでは止めない（DM を使わない人には要らないため） |

## 7. 文言の書き方

前の版の文言は、英語の構文をそのまま日本語にしたものでした（「〜を通して」「〜するのに使います」「誰でも〜できます」「〜以外は〜しません」）。文言は、**その 1 文で利用者にどう考えてほしいか**から書きます。

- 1 文で伝えることは 1 つ。結論を先に書く。
- 主語は、自然に省けるなら省く。機械を主語にした「SockDock は〜します」を並べない。
- 見出し・ボタン・ラベルは体言（「Slack に接続」「Web 検索」）、文は「です・ます」。
- 二重否定（「〜以外は〜しません」）を使わず、肯定で言い切る。
- 用語はルビのように補わない。分からない人のための説明を足すより、言葉を変える。

## 8. 画面と文言

「伝えたいこと」は、その文言を読んだ利用者に持ってほしい考えです。画面には文言だけを載せます。

### セットアップ 1 — Slack アプリを作成

読む人: 初めて SockDock を使う人。多くは新しく作る。手元にある Slack アプリ（通知用のボットなど）を使いたい人もいる。
伝えること: 新しく作るなら、ボタンを押していけば終わる。すでにあるアプリも使えるが、設定をそろえる必要があり、そのアプリの動きが変わることがある。2 つのトークンは同じアプリから取る。

| 文言 | 伝えたいこと |
|---|---|
| **Slack アプリを作成** | — （見出し） |
| SockDock 用の Slack アプリを作ります。 | 次にすることは Slack 側の作業 |

#### 投稿の条件

見るのはトップレベルの投稿だけです。スレッドの返信は条件を見ずに、そのスレッドのルールで続けます（§3）。

| 選択肢 | 動く（キーワード: review / 相談） | 動かない | プログラムに渡す本文 |
|---|---|---|---|
| 〜で始まる投稿（新しいルールの初期値） | `review src/api.ts`、`Review`、`@アプリ review`、`相談したい` | `reviewer`、`please review` | キーワードの後ろ |
| 〜を含む投稿 | `please review`、`ちょっと相談です` | `reviewer` | 投稿全体 |
| 正規表現に一致する投稿 | 一致した投稿 | — | 名前付きグループ |
| すべての投稿 | すべて | — | 投稿全体 |

AI エージェントには、どの選択肢でも投稿全体を渡します。

照合のしかた（キーワードの 2 つ）:

- 大文字と小文字、全角と半角（英数字・空白・記号）を区別しない。
- 先頭の、Slack アプリへのメンションは無視する。
- 英数字のキーワードは、英数字の単語の途中では一致しない（review は reviewer に一致しない）。日本語は単語を区切らないので、「相談」は「相談したい」に一致する。
- キーワードには空白を含めてよい（`code review`）。空白の数の違いは区別しない。
- 正規表現は、メンションを除いただけの本文に当てる。大文字と小文字は区別する（区別しないなら `(?i)` を書く）。
- どの選択肢でも、Slack が `&amp;` `&lt;` のように送ってくる記号は元の文字に戻してから比べる。

「メンションされたときだけ」（どの選択肢にも付けられる）:

- 本文のどこかに Slack アプリへのメンションがある投稿だけを、条件に当てる。メンションのない投稿では、そのルールは「ない」ものとして扱う（オフのルールと同じく、下に合うルールがあれば、そちらが動く）。
- 条件の照合は上と同じ。先頭のメンションは無視するので、「`@アプリ review src/api.ts`」は「review で始まる・メンションされたときだけ」に合い、「`review src/api.ts`」は合わない。
- 「上のルールに先に合うため、動きません」は、上のルールがメンションされたときだけでないときに出す（上がメンションされたときだけなら、メンションのない投稿は下に届く）。
- DM では使わない（DM は Slack アプリに宛てたものなので）。

ルールが重なったとき:

- 1 つの投稿で動くルールは 1 つ（1 つのスレッドで続ける会話は 1 つ）。
- 同じチャンネルのルールを一覧の上から順に見て、最初に合ったルールを動かす。順番は一覧のドラッグで変える。
- オフのルールは飛ばす（下に合うルールがあれば、そちらが動く）。
- 新しいルールは、そのチャンネルのいちばん下に入る。チャンネルを変えたルールも、移った先のいちばん下に入る。
- 上のルールに必ず先に合うと分かるルールには、一覧の行に問題として出す。分かるのは、上に「すべての投稿」があるとき、同じ条件のとき、キーワードが上のルールのキーワードで始まる（「含む」なら、含む）とき。正規表現は調べない。

#### 実行できる人

ルールごとに決めます（2026-11-14、ユーザー確認済み）。許可の広いルールと狭いルールが同じチャンネルにあっても、広いほうだけを絞れます。

| 決めたこと | 内容 |
|---|---|
| 既定 | 新しいルールは「全員」（今と同じ）。SockDock は「自分」が誰かを知らないので、「自分だけ」を既定にしない。絞りたくなったルールだけ「選んだ人」にする。本人（§8「本人」）を登録しても、チャンネルのルールの既定は変えない（2026-11-14、ユーザー確認済み）。DM のルールだけは本人で始まる |
| 選び方 | 人を名前で選ぶ（`users:read`）。ユーザーグループは選ばない |
| 選ばれていない人の投稿 | 何もしない（👀 も返信も付けない） |
| 選ばれていない人のスレッドへの返信 | 無視する。そのときも、あとで選ばれた人が返信したときも、AI エージェントやプログラムに渡さない |
| すでにあるルール | 全員のまま（設定ファイルに書かれていなければ全員）。更新で動きは変わらない |

照合のしかた:

- 選ばれていない人の投稿では、そのルールは「ない」ものとして扱う。オフのルールと同じく、下に合うルールがあれば、そちらが動く。
- 実行できる人は、投稿や返信が届いたときの設定で決める。あとで人を外せば、その人が始めたスレッドでも、その人の返信は無視する。
- 一覧の「上のルールに先に合うため、動きません」は、上のルールが全員のときだけ出す。上のルールが選んだ人なら、ほかの人の投稿は下に届くため。

#### DM とメンション

2026-11-14 にユーザーが決めたこと（仕様の全体は [`docs/design.md`](design.md) §3.5。2026-11-14 に承認済み）:

| 決めたこと | 内容 |
|---|---|
| DM の区切り | チャンネルと同じ。DM のトップレベルのメッセージ 1 つで始まり、返信はそのスレッドに付け、続きはスレッドで話す |
| DM のルールを動かせる人 | 「実行できる人」の仕組みに乗せる。新しい DM のルールは、本人を選んだ状態で始まる。ほかの人を足すことも、全員にすることもできる |
| メンション | 条件に付ける「メンションされたときだけ」。新しい条件は足さない |
| スレッドの途中のメンション | 今と同じく、ルールを始めない |

あわせて決めたこと（2026-11-14 承認）:

- ルールのチャンネルの選択肢に「DM」を足す。誰との DM でも、同じ DM のルールで見る（人ごとにルールを分けたいときは、実行できる人で分ける）。
- DM のルールは、一覧でチャンネルの後ろにまとめる。メニューと通知では `DM「キーワード」` と呼ぶ。

#### 添付ファイル

#### 本人

SockDock を使っている人を、Slack のメンバーとして登録します。Slack と Mac の両方を触れる人だけが登録できます。登録すると、通知を DM で受け取れ、新しい DM のルールの「実行できる人」に最初から入ります。

流れ（2026-11-14、ユーザー確認済み）: Mac で［本人を登録］を押す → Mac にワンタイムコード（TOTP）が出る → 本人がそのコードを Slack アプリに DM で送る → コードが合えば、送った人を本人として登録する。

- 登録は、Mac で始めたときだけ受け付ける。始めていないときの DM は、登録には使わない。
- コードは Mac の画面にしか出ないので、正しいコードを送れるのは、Mac と Slack の両方を触れる人だけ。画面を見た別の人が先に送ると、その人が登録されるが、Mac に名前が出るので、解除してやり直せばよい（ユーザー確認済み）。

| 文言 | 伝えたいこと |
|---|---|
| （登録していない）通知を Slack の DM で受け取れます。 ［本人を登録］（「本人」の見出しは出さない） | 登録すると何ができるか。登録はここから始める |
| （始めた）**482 913** ［コピー］ ／ このコードを、Slack アプリに DM で送ってください。 ［キャンセル］（見出しは出さない） | することは、コードを DM で送るだけ。コードは 30 秒ごとに変わる（残り時間は数字の横の小さな円で示す。文では書かない） |
| （登録した）本人 田中 太郎 ［解除］ | 登録できた。思っていた人でなければ、解除してやり直す |
| （10 分たった・違うコードが 5 回届いた）文は出さず、「登録していない」の表示に戻す | コードが消えたので、もう使えない。もう一度押せば新しいコードが出る（ユーザー確認済み） |
| （`users:read` がない）名前の代わりにメンバー ID を出す（本人 `U0123ABCD` ［解除］） | 名前が分からなくても登録できる |
| （`im:history` がない）Slack アプリに `im:history` のスコープがないため、本人を登録できません。（［本人を登録］は出さない） | 登録できない理由。コードを送る DM が届かない |

あわせて決めたこと（2026-11-14 承認）:

- ［コピー］は今のコードを空白なしでコピーし、2 秒だけ［コピーしました］にする（MCP の欄と同じ）。打ち写さずに DM に貼れる（2026-11-14、ユーザーの依頼）。
- コードは 6 桁の TOTP（30 秒ごと）。打つ間に変わっても通るように、1 つ前のコードも受け付ける。空白や全角の数字は区別しない。
- 始めてから 10 分たつか、［キャンセル］を押すと、コードを受け付けなくなる。DM を送るために Slack に切り替えても、受け付けは続く。10 分の上限は画面に出さない（ユーザー確認済み）。
- 受け付けている間は、6 桁の数字だけの DM をコードとして扱い、DM のルールには渡さない。ほかの DM は、いつもどおり DM のルールで見る。
- 違うコードには、DM で「⚠️ コードが違います。」と返す（§3「本人への DM」）。5 回違ったら、受け付けをやめる。10 分たったときと同じく、画面には何も出さずに「登録していない」の表示に戻す（ユーザー確認済み）。
- コードが合ったら、送った人を本人にして、その DM に「✅ 登録しました。SockDock からのお知らせは、この DM に届きます。」と返し、通知の「Slack の DM」をオンにする（登録するのは、たいてい DM で知らせてほしいため）。
- 解除しても、DM のルールの実行できる人からは外さない（ルールにはメンバー ID で入っているので、そのまま残る）。
- MCP からは登録も解除もできない（§10）。

あわせて決めたこと（2026-11-14 承認）:

- ダイアログは SockDock のウィンドウを開き、その中に出す（ルールの画面の「初期状態に戻す」の確認と同じ形）。macOS 標準のダイアログは長い文や箇条書きに向かないため。
- リリースノートは、箇条書き・`コード`・**太字** だけを描く。リンクは文字として出し、押せるのは「GitHub で見る ↗」だけにする。GitHub から取ってきた文を、画面に HTML として入れないため。長ければ、ダイアログの中でスクロールする。文字は本文より小さく（11px）し、行の間も詰める（2026-11-14、ユーザーの依頼）。
- 版は先頭の `v` を付けずに書く（`0.2.0`）。
- 更新でターミナルに出す最初の行は「SockDock を 0.2.0 に更新します。」だけにする。そのあとは Homebrew の出力。
- 更新の途中で、Homebrew がアプリを終了させる。更新が終わったら、ターミナルからアプリを開き直す。失敗したら、アプリは開き直さず、ターミナルに Homebrew のエラーが残る。
- 手元でビルドした版（版が `v0.1.1-6-g7e68b09` のような形や `dev`）は確かめない。
- CLI だけで動かしている人（`sockdock service`）には、DM と `sockdock status` で知らせる。メニューバーがないので、更新はしない。

### メニューバーのメニュー

| 文言 | 伝えたいこと |
|---|---|
| ● Slack に接続済み | 動いているか |
| 処理中: `#dev-help「review」` 42 秒 | いま何が動いているか（選ぶとスレッドを開く） |
| 最近の処理: 5 件 | さっきのは成功したか（選ぶとそのルールを開く） |

| SockDock を開く ／ 設定… ／ SockDock を終了 | — |

### 通知

送り先は Mac（macOS の通知）と Slack の DM（本人への DM）の 2 つで、設定の「通知」でそれぞれオン・オフします（2026-11-14、ユーザー確認済み）。DM の文言は §3「本人への DM」。

| 文言（Mac） | Mac | Slack の DM | 伝えたいこと |
|---|---|---|---|
| `#dev-help「review」` の処理が失敗しました | 送る | 「処理の失敗も送る」がオンのときだけ。既定はオフ（ユーザー確認済み） | どのルールが失敗したか（押すとそのルールを開く）。失敗はスレッドにも出るので、DM では普段は送らない |
| Slack に接続できません | 送る | 送らない | 押すと設定の Slack を開く。つながらない間は DM も送れない |
| Claude Code にサインインしていません | 送る（新しく足す） | 送る | AI エージェントのルールがどれも動かない。押すとルールの一覧を開く（バナーがある）。サインインし直すまで、もう送らない |
| MCP から `#dev-help「review」` を変更しました（追加・削除・並べ替え・オン/オフも同じ形） | 送る。オフでも出す | 送る。Slack の DM のスイッチに従う | 自分の知らない変更なら、すぐ気づける（押すとそのルールを開く。削除なら一覧を開く）。Mac はオフでも出すので、DM まで強制しない |
| SockDock 0.2.0 が出ました | 送る | 送る | 新しい版がある。更新はメニューバーの「SockDock 0.2.0 に更新…」から。版ごとに 1 回だけ（§8「新しい版」） |

### アイコン

差込口に顔を付けた形。右の三角の切り込みが口、縦の差込口 2 つが目。切り込みのある四角は C にも K にも見え、名前の「-ck」の韻を形に入れている。色は裏方らしい藍紫（`#3C3489`）。

| 場面 | 利用者の問い | 見せるもの |
|---|---|---|
| アプリ（Dock・Finder・通知） | これは何のアプリか | 藍紫の角丸四角に、白い顔 |
| メニューバー | 動いているか | 白黒の顔。接続済み: 目を開ける ／ 処理中: 右上に点 ／ 接続できません: 目を閉じる |
| Slack の返信 | この返信は誰からか | アプリと同じ絵 |
| Claude Desktop の拡張機能 | どの拡張機能か | アプリと同じ絵 |

- 接続できないときも薄くしない。表情で伝わるうえ、macOS では薄いアイコンが「使えない」に見える。
- Slack はマニフェストでアイコンを決められないので、利用者が Slack アプリの設定で画像を上げる。必須ではないので、セットアップには出さない（§1 オンボーディング）。画像は README で案内する。

## 9. 言葉

| 言葉 | 意味 |
|---|---|
| Slack アプリ | 利用者が api.slack.com で作るもの。名前は利用者が決めるので、画面では固定の名前で呼ばない |
| トークン（App-Level Token / Bot Token） | Slack アプリの鍵。`xapp-` / `xoxb-` |
| ルール | 「チャンネル・反応する投稿・実行するもの」の組。メニューと通知では `#チャンネル「キーワード」` で呼ぶ（正規表現は `#チャンネル /パターン/`、すべての投稿は `#チャンネル`）。一覧の行では「で始まる」「を含む」まで書く |
| 反応する投稿 | ルールが動く投稿の条件。〜で始まる / 〜を含む / 正規表現に一致する / すべての投稿 |
| 実行できる人 | ルールを動かせる人。全員（チャンネルのメンバー全員。DM ではワークスペースの誰でも）か、選んだ人。「許可」は AI エージェントにさせてよい操作のことなので、人には使わない |
| 本人 | SockDock を使っている人。Mac に出るコードを Slack アプリに DM で送って登録する。通知の DM の送り先で、新しい DM のルールの実行できる人に最初から入る。「自分」「オーナー」とは呼ばない（画面の主語が利用者なので「自分」は紛れ、「オーナー」は Slack の権限の言葉と紛れる） |
| 添付ファイル | 投稿や返信に付いたファイル（画像、ログ、PDF など）。ルールが動くと、本文と一緒に AI エージェントやプログラムに渡る。「ファイル」だけだと作業フォルダのファイルと紛れるので、Slack のものは「添付ファイル」と呼ぶ |
| DM | Slack アプリへのダイレクトメッセージ。ルールのチャンネルの代わりに選べる。誰との DM でも同じ DM のルールで見る |
| メンションされたときだけ | 条件に付けるもの。Slack アプリをメンションした投稿でだけ、そのルールが動く |
| 処理 | ルールが 1 回動いたこと。結果は 成功 / 失敗 / 時間切れ / 停止 / 処理中 |
| オン / オフ | ルールが投稿に反応するかどうか |
| AI エージェント | ルールが動かすもの。Claude Code と Codex（Codex は 2026-11-15 に決定、§8「エージェントと、許可の項目」）。許可を守れると確かめたものから足す。画面では製品の名前で呼ぶ: Claude Code ／ Codex（「Codex CLI」の「CLI」は付けない） |
| 接続済み / 接続できません | Slack とのつながり |
| MCP | Claude Code・Codex などのクライアントから SockDock を操作するしくみ。ルールが動かす AI エージェントとは別のものなので、「AI エージェント」とは呼ばない |

## 10. 載せないもの

- 仕組みの言葉（ゲートウェイ、Socket Mode、pid、キーチェーンの詳細、環境変数）
- 起動・停止・再起動のボタン（つながらなければ SockDock が自分でつなぎ直す）
- Slack の画面の道順（Slack の画面は変わる。やることとスコープの名前だけを書く）
- 新しく作る人の画面に、Slack アプリの細かい設定（Socket Mode・イベント・スコープ）。ボタンで作れば入る。すでにあるアプリを使う人には、畳んだ入口の中だけに出す
- セットアップの「試す」手順（投稿が届くかは、最初のルールで分かる。届かないときの手がかりはルールの画面に置く）
- Slack アプリの固定の名前（§5）
- ルールの名前の欄（`#チャンネル「キーワード」` で呼ぶ）
- 後方一致・完全一致の選択肢（後方一致は使い道がない。完全一致は「〜で始まる」で足りる）
- 優先度の数字（順番は一覧の上下で表す）
- 全体の履歴の画面、ログの画面、設定ファイルのエディタ
- 「保存しました」などの結果の文（画面の変化でわかる）
- 選ばれていない人の投稿への返信やリアクション、その投稿の記録（ルールに合わない投稿と同じ扱い）
- 一覧の行の、実行できる人（どの投稿で何が動くかが行の役目。誰が動かせるかはルールの画面で見る）
- 最近の処理の、投稿者の名前（スレッドを開けば Slack で分かる）
- 設定の別ウィンドウ（§4）
- スレッドの途中のメンションでルールを始めること（ユーザー確認済み）
- 新しい版の、変更点の要約（リリースノートへのリンクだけ。2026-11-14、ユーザー確認済み）
- 設定の版の行の「新しい版があります」（知らせる場所はメニューバー・Mac の通知・DM。2026-11-14、ユーザー確認済み）
- アプリが自分で新しい版を落として置き換える更新（Homebrew の記録と食い違うため。更新は Homebrew で行う）
- 登録を始めていないときの DM を、本人の候補として出すこと（登録は Mac で始めたときだけ）
- コードの残り秒数の文（数字の横の小さな円で示す）
- 登録の受け付けをやめた理由（10 分たった・違うコードが 5 回届いた）。どちらも「登録していない」の表示に戻すだけ
- 本人を MCP から登録・解除すること（Slack と Mac の両方を触れる人だけが登録できる、という前提を守るため）
- 「メンションされたときだけ」の DM での表示（DM は Slack アプリ宛てなので要らない）
- 添付ファイルの置き場所・消すとき・上限（20 MB）の説明（上限を超えたことは、AI エージェントが返信で伝える）
- 渡せなかった添付ファイルの定型文（ハンドラが伝える。ユーザー確認済み）
- ルールごとの「添付ファイルを渡す」（いつも渡す。ユーザー確認済み）
- 最近の処理の、添付ファイルの名前（投稿者の名前と同じく、スレッドを開けば分かる）

## 11. この画面に必要な実装の変更

2026-11-14 時点で、1・2・4〜12・15〜17・19〜21 と、14 のうち画面と定型文は実装済み（18 は 19 で取り下げ）。残りは 3・13・22 と、14 の設定ファイルのキー。23 は 2026-11-14 に実装した（本物の Slack で名前を選ぶところは未確認）。

1. **再接続**: つながらなくなっても、つながるまで試し続ける。起動・停止のボタンをなくすための前提。ゲートウェイは 5 分で止まるが、アプリが 15 秒後に起動し直すことで満たす。
2. **トークンの扱い**: 「Slack に接続」で、確かめてから保存する（いまは先に保存する）。App-Level Token のスコープ不足を見分けて伝える。Bot Token をプログラムに環境変数で渡すのをやめる（「送信先は Slack だけ」の前提）。
3. **許可**: 許可していない操作を実行しない。いまはコマンドを 1 つ許可すると、読み取りのコマンドがフォルダの外にも効く。
4. **反応する投稿**: 4 つの選択肢と、照合のしかた・重なったときの決め方を §8「投稿の条件」のとおりにする。
    - オフのルールは飛ばして、次に合うルールを動かす。
    - 順番は設定ファイルの並びをそのまま使う。一覧はチャンネルごとにまとめ、ドラッグした順を設定ファイルの並びに書き戻す。先に合うルールがあるときは、行の問題として出す。
    - 設定ファイルには条件の種類をキーで書く（`starts_with` / `contains` / `match` / `all_posts`）。以前の版がキーワードを正規表現にして `match:` に書いたものは `starts_with` として読む。`sockdock match` も同じ照合を使う。
5. **ルールの問題**: 1 つのルールの問題で、ほかのルールを止めない。
6. **ルールの名前**: 自動で付ける。
7. **処理の記録**: 失敗の理由、スレッドへのリンクを持つ。処理を停止できるようにする。ルールごとに最近の処理を取れるようにする。
8. **チャンネル**: 貼られた ID・リンクの名前を `conversations.info` で引く。
9. **言語**: 画面の言語と、Slack への定型文の言語を 1 つの設定にする。
10. **マニフェスト**: 作成ページを、マニフェストが入った状態で開く（`manifest_yaml=`）。
11. **メニューバー**: ポップオーバーをメニューにする。
12. **Slack への定型文**: §3 の文にする。固定の名前、ルールの名前、「ログ」を含めない。英語も同じ考えで書き直す。Mac の画面で停止したときの文を足す。
13. **AI エージェント**（2026-11-15 に取り下げ。CLI を直接動かす 28 に置き換えた）: Agent Client Protocol（ACP）で動かす（試作: [`docs/research/acp-spike.md`](research/acp-spike.md)）。
    - エージェントごとにプロセスを 1 つ持ち、Slack のスレッドごとにセッションを 1 つ持つ。再起動のあとは resume、だめなら load、それもだめなら新しいセッションで続ける。
    - 許可の求めは、ルールの許可の設定で 1 か所で判定する。答えは `allow_once` か `reject_once` だけにする。3 の解決も兼ねる。
    - エージェントごとに、緩い初期値を締める設定を注入する（Claude Code: モード `default`、Bash は毎回確認、利用者の設定を読まない）。
    - エージェントのコマンドは設定で指定する（いまの `claude_command` と同じ）。ログインは各 CLI で済ませてもらう。
    - 最初は Claude Code だけ。本物のモデルで 1 回確かめてから、`claude -p` の処理を ACP に置き換える。Codex と Gemini CLI は、ログインした環境で許可の求めを確かめてから足す。
14. **呼び方**: 画面・定型文・設定ファイルの説明で「ルート」を「ルール」にする（`routes:` などの設定ファイルのキーも合わせて変えるかは実装時に決める）。
15. **MCP**: [`docs/mcp.md`](mcp.md) のとおり。`sockdock mcp`、制御 API のルール単位の口、設定の「MCP」の行、MCP からの変更の通知。
20. **Claude Desktop の拡張機能**: 設定の「MCP」で Claude Desktop を選ぶと、アプリに同梱の CLI から `SockDock.mcpb`（MCPB の binary 形式）を作って開く（[`docs/mcp.md`](mcp.md) §2.1）。
16. **ウィンドウを 1 つに**: 設定のウィンドウをなくし、メインのウィンドウの［ルール｜設定］にする。⌘, と「設定…」は「設定」の表示で開く。
17. **初期状態に戻す**: §8「初期状態に戻す」のとおり。
18. **スコープの表示**: （19 で取り下げ。セットアップ 1 に一覧は出さない）
19. **セットアップと、届かないときの手がかり**: セットアップ 1 に、新しく作る手順と、畳んだ「すでにある Slack アプリを使う」（設定の名前・マニフェストの該当部分のコピー・Socket Mode の注意・再インストール）を出す。セットアップ 2 で Bot Token のスコープを `x-oauth-scopes` で確かめ、必須が足りなければ止める。ゲートウェイが、つないでから投稿が届いたチャンネルを覚え、ルールの画面で「まだ届いていません」と「届かないとき」を出す。
21. **Claude Code のサインイン**: SockDock が動かすのは設定の `claude_command`（コマンドラインの Claude Code）で、Claude のデスクトップアプリのサインインとは別。
    - 確かめ方: `claude_command auth status` の `loggedIn`。起動したとき、ウィンドウに戻ったとき（30 秒に 1 回まで）、処理が認証のエラーで失敗したときに確かめる。分からないとき（`auth status` がない古い版など）は何も出さない。期限が切れても更新できるトークンで `loggedIn` が true になるかは、実装のときに確かめる。
    - ［ターミナルでサインイン］: `claude_command auth login` を実行する `.command` ファイルを作って開く（ターミナルの `claude` が動かない環境でも、SockDock が使う Claude Code にサインインできる）。
    - 処理の失敗: Claude Code の認証のエラー（`Failed to authenticate` など）は、理由を「Claude Code にサインインしていません」にする。Slack の定型文は変えない（直すのは Mac なので、「理由は Mac の SockDock で確認できます」で足りる）。
    - MCP: `sockdock_get_status` と `sockdock_check_rule` でも伝え、手引きに「利用者にターミナルでのサインインを頼む」と書く。
22. **アイコン**: §8「アイコン」のとおり。`internal/brand` の絵を描き直す（アプリと、メニューバーの 3 状態）。Claude Desktop の拡張機能のマニフェストに `icon` を足す。Slack 用の PNG（512px 以上）を `assets/` に置き、README から案内する。
23. **実行できる人**: §8「実行できる人」と [`docs/design.md`](design.md) §3.4 のとおり。マニフェストに `users:read` を足す。ルールの画面に「実行できる人」を足す。ゲートウェイは、選ばれていない人の投稿と返信を捨てる。MCP の手引きとツール、[`docs/mcp.md`](mcp.md) も合わせる。
24. **DM とメンション**（2026-11-14 承認・実装。本物の Slack では未確認）: §8「DM とメンション」と [`docs/design.md`](design.md) §3.5 のとおり。ルールのチャンネルに「DM」、反応する投稿に「メンションされたときだけ」を足す。マニフェストに `im:history`・`message.im`・Messages タブを足す。
25. **本人と、DM の通知**（2026-11-14 承認・実装。本物の Slack では未確認）: §8「本人」「通知」と [`docs/design.md`](design.md) §3.5 のとおり。設定の Slack に本人、通知を Mac と Slack の DM に分ける。DM の文言は §3「本人への DM」。
26. **添付ファイル**（2026-11-14 承認・実装。本物の Slack では未確認）: §8「添付ファイル」と [`docs/design.md`](design.md) §3.6 のとおり。マニフェストに `files:read`（任意）を足す。ゲートウェイがルールの動いた投稿のファイルを取り、AI エージェントには `<slack_file>` と Read の許可を、プログラムには `messages[].files` を渡す。ルールの画面の「最近の処理」に、`files:read` がないことを出す。セットアップ 1 の任意のスコープに足す。
